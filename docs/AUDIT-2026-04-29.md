# Audit Log: Section 0 Correction - 29 April 2026

## Why These Changes Were Made

The Canonical Alignment document dated 28 April 2026 establishes a Section 0 leverage principle: all R22 mainnet plumbing is frozen-in-place, and all new capability must be additive only, never duplicating or competing with frozen mainnet authorities.

The prior state of `@ctpip/core` violated Section 0 by using module names that collided with canonical on-chain authorities (LUX Runtime, Guardian Gates), returning output fields that mimicked canonical EVA output (`ctu`, `verdict: VALID`), citing a superseded DOI and corpus version (R11), and having no non-authoritative framing. This produced canonical ambiguity.

This audit corrects the SDK to be a Section 0-compliant non-authoritative reference package.

## What Was Renamed

| Before | After | Reason |
|:-------|:------|:-------|
| `evaluateEVA()` | `estimateLocalCoherence()` | Avoids implying canonical EVA execution |
| `EVAResult` | `LocalCoherenceEstimate` | Output is a local estimate, not a canonical result |
| `EVAInput` | `CoherenceInput` | Neutral name without EVA branding |
| `Verdict` enum | `CalibrationCheck` enum | Not a canonical verdict |
| `Verdict.VALID` | `CalibrationCheck.PASSES_LOCAL_CALIBRATION` | Cannot claim canonical validity |
| `Verdict.INVALID` | `CalibrationCheck.FAILS_LOCAL_CALIBRATION` | Cannot claim canonical invalidity |
| `EVACalibration` | `CoherenceCalibration` | Neutral name without EVA branding |
| `eva.ts` | `coherence.ts` | Module no longer named after on-chain authority |

Classification enum (SEED/BLOOM/ROOT) stays but is now documented as band labels for UI preview only.

## What Was Removed

- **Guardian Gates module** (`gates.ts`): Entire file removed. `evaluateGates`, `GateResult`, `GateEvaluation`, `CausalAnchor`, `SealAttempt` -- all gate-related exports removed. Guardian Gates are on-chain validation gates in the Solana program; an SDK should not duplicate them. A future separate package (`@ctpip/repo-actions`) will ship Git-CI gates under a different name.
- **`ctu` field**: Removed from all output types. CTU is minted on-chain by LUX Runtime only. Replaced with `gammaEstimate` (number, 0-1) with explicit non-authoritative comment.
- **Level 0 Invariants section** from README: Replaced with "Protocol Constants (Reference Only)" section that explicitly states enforcement happens on-chain.
- **R11 Sealed Unified Corpus references** and DOI `10.5281/zenodo.19362640`: Superseded. Replaced with R2/R22 references and historical R1 DOI.
- **SE-SPEC 2.1 Part XII reference**: Not a published document. Replaced with canonical R2 corpus citation.
- **Keywords**: `lux-runtime`, `guardian-gates`, `proof-of-transformation` removed from package.json.
- **`computeCTU()` function**: Removed from coherence module. CTU computation is canonical-only.

## What Was Added

- **Non-authoritative banner** at top of README with canonical authority addresses (Program, LUX Runtime Oracle PDA, FLUX Mint).
- **TKDF-256 public standard documentation** section in README explaining anyone can compute, only LUX Runtime Oracle PDA can sign.
- **Test vectors** (`tests/tkdf256-vectors.json`): 5 input-output pairs covering Origin, Creation, Identity, Work, and Competency domains.
- **Test suite**: 43 tests across coherence estimation, TKDF-256 vectors, and Section 0 naming compliance audit.
- **This audit log** (`docs/AUDIT-2026-04-29.md`).

`1.0.0` downgraded to `0.1.0`. The prior 1.0.0 was incorrect for a pre-1.0 non-authoritative reference SDK.
